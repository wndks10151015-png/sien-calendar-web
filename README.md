# Sien Calendar Web

Obsidian 없이 브라우저에서 실행하는 개인용 캘린더 초기 버전입니다. 기존 4.26.42 엔진의 월·주·목록·표·프로젝트 뷰를 재사용합니다.

## 저장과 비용

- 공개 저장소에는 앱 코드·스타일·폰트·아이콘만 둡니다. 일정 JSON, iCal 구독 주소, 접근 토큰은 넣지 않습니다.
- 일정은 별도의 **비공개 GitHub 저장소**에 저장하고 각 기기는 GitHub API로 직접 동기화합니다. PC를 켜 둘 필요가 없습니다.
- GitHub Free와 Pages만 사용합니다. 유료 플랜·결제 수단·별도 서버·GPT 계정이 필요하지 않습니다. 한도 초과 시 유료 전환하지 않고 동기화를 보류합니다.
- API 호출 한도는 인증된 사용자 기준 보통 시간당 5,000회이며 다른 도구와 공유합니다. 콘텐츠 쓰기에는 별도의 보조 한도가 있습니다. Pages는 배포 크기 1GB, 월 100GB 소프트 대역폭 제한이 있습니다. [API 공식 한도](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api) · [Pages 공식 한도](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

## 기기 연결

1. 본인 GitHub 계정에 비공개 일정 저장소를 만듭니다. `calendar.json`에 기존 Sien Calendar schema 11 데이터를 둘 수 있습니다.
2. [Fine-grained 토큰 설정](https://github.com/settings/personal-access-tokens/new)에서 **그 비공개 저장소 하나만** 선택합니다. Repository permissions의 **Contents: Read and write**를 허용합니다. 계정 전체 권한이나 공개 앱 저장소의 쓰기 권한은 주지 않습니다.
3. 앱 오른쪽 위 동기화 버튼에서 소유자·비공개 저장소·토큰과 10자 이상의 기기 잠금 비밀번호를 입력하고 로그인합니다. 각 기기에서 한 번씩 연결합니다. 토큰을 채팅·이슈·공개 파일에 붙여넣지 마세요.
4. 로그인은 별도 체크 없이 이 기기에 유지됩니다. 토큰은 PBKDF2-SHA256 600,000회와 AES-GCM으로 암호화하여 브라우저에만 보관합니다. 앱을 다시 열면 토큰 대신 기기 잠금 비밀번호로 해제합니다. 저장 실패는 로그인 완료로 처리하지 않습니다. 예전 버전에서 토큰 기억하기를 끈 기기는 한 번 다시 로그인해야 하며, 그동안 만든 로컬 일정은 보존합니다.
5. 휴대폰·태블릿 브라우저의 ‘홈 화면에 추가/앱 설치’를 사용할 수 있습니다. 오프라인 사용 전에는 온라인에서 앱을 열고 동기화를 마쳐 두세요.

토큰은 앱 페이지 서버로 보내지 않고 `api.github.com` 인증 헤더로만 보냅니다. 만료·폐기한 토큰은 새 토큰으로 다시 연결해야 합니다. 로컬 잠금 비밀번호는 서버로 보내지 않습니다. 분실 시 토큰을 재발급해 연결을 다시 설정할 수 있습니다.

## 동기화 규칙과 주의사항

- 편집 후 약 1.8초 뒤 업로드를 시도합니다. 앱이 보이는 동안 원격 변경은 약 60초 간격과 창 복귀 시 확인합니다. 실시간 공동 편집 서비스는 아닙니다. 기기를 바꾸기 전 ‘동기화 완료’를 확인하세요.
- 서로 다른 항목·필드의 편집은 3-way 병합합니다. 같은 필드를 동시에 바꾸면 자동 덮어쓰기하지 않고 선택을 요청합니다. SHA 충돌 시 최신 원격 데이터를 다시 읽습니다.
- 로그인과 실제 업로드 완료를 구분합니다. 토큰이 없거나 만료되면 캘린더에 재로그인 경고를 표시합니다. 미전송 편집이 있으면 브라우저를 닫을 때 경고를 요청하지만, 모바일 강제 종료·OS 메모리 회수까지 막지는 못합니다.
- 최초 연결에 앞서 이 기기에서 만든 프로젝트·설정·일정을 빈 문서로 간주하지 않습니다. 기준본이 없어 같은 설정을 합칠 수 없으면 명시적인 선택이 필요합니다. 최초 연결과 충돌 선택 전에는 최근 5개의 서로 다른 로컬 복구본을 보관하며, 동기화 창의 ‘복구본 내보내기’에서 JSON으로 받을 수 있습니다. 모든 편집의 자동 이력은 아니며, 브라우저 데이터가 삭제되면 함께 없어집니다.
- 프로젝트·속성·외부 캘린더는 안정적인 식별자별로 병합하고, 양쪽에서 추가만 한 프로젝트 선택지는 함께 보존합니다. 삭제 대 편집 같은 모호한 변경은 계속 선택을 요청합니다. 서버 파일이 갑자기 없어지거나 응답이 손상되면 로컬 일정을 지우거나 원격에 빈 문서를 만들지 않습니다.
- 현재 뷰·달력 배율·주간 표시 일수·종일 영역 크기·표 열 배치와 너비는 기기별로 유지합니다. 이 값들은 브라우저의 로컬 문서에 남지만 공유 일정의 충돌 비교·업로드에서 제외합니다. 저장된 보기의 이름·필터·속성 바인딩과 수동 행 순서는 계속 공유하며, 보기 목록은 ID와 필드별로 병합합니다. 새 보기의 최초 유형은 새 기기를 위한 기본값으로 보존합니다.
- 보기만 바뀌며 증가한 내부 저장 시간·횟수는 원격 저장을 만들지 않습니다. 기존 버전의 `config/savedViews` 보기 상태 충돌은 다음 동기화에서 기준본을 초기화하거나 일정을 다시 가져오지 않고 정규화합니다. 실제 일정의 같은 필드나 공유 설정의 같은 필드에 대한 동시 편집은 여전히 선택이 필요합니다.
- 공개 저장소는 일정 읽기와 쓰기 모두 거절합니다. 비공개 여부를 동기화 전과 쓰기 전에 다시 확인합니다. 사용자 본인이 GitHub 설정에서 데이터 저장소를 공개로 바꾸면 과거 커밋까지 노출될 수 있으므로 **절대 공개 전환하지 마세요**.
- 현재 앱은 일정 JSON 20MB, 수동 ICS 파일 10MB까지 허용합니다. GitHub 저장소와 커밋 이력도 무제한 저장소는 아니며 장기 운영 시 백업·정리가 필요할 수 있습니다.
- 브라우저의 일정 캐시는 오프라인 사용을 위한 **암호화하지 않은 IndexedDB**입니다. 토큰 암호화와 데이터 종단간 암호화는 다릅니다. 기기·브라우저 프로필을 보호하고 정기적으로 JSON을 내보내세요. 브라우저 데이터 삭제·시크릿 모드·저장공간 회수 시 로컬 변경이 사라질 수 있습니다.
- 원본 Obsidian 데이터는 한 번 가져오는 방식입니다. 기존 플러그인/Syncthing과 웹앱 사이의 자동 양방향 연동은 없습니다. 웹앱으로 전환한 뒤 양쪽을 병행 편집하면 서로 자동 반영되지 않습니다. 원본은 백업으로 보존하세요.
- iCal 주소가 CORS를 허용해야 브라우저에서 직접 새로고침할 수 있습니다. 그렇지 않으면 동기화 창의 **ICS 가져오기**로 파일을 추가/교체하세요. 일반 일정·공휴일 표시 방식과 색상을 선택할 수 있고 이 캐시는 다른 기기로 동기화됩니다. ICS 파일 자체는 자동 갱신되지 않습니다. 비공개 구독 주소를 공개 프록시에 보내지 않습니다.
- 첨부파일 동기화가 지원되지 않으므로 웹 버전의 파일 보관함·첨부파일 속성·프로젝트 파일 탭은 제거했습니다. 링크 속성은 그대로 사용하며, 기존 JSON에 들어 있는 첨부 메타데이터나 기기 내 파일을 삭제하지 않습니다. Obsidian 보관함·Markdown 링크·플러그인 명령은 브라우저에서 자동 접근하지 않습니다. 기존 Android 위젯과의 연결도 이번 웹 버전에서는 검증하지 않았습니다.
- 앱이 닫힌 상태의 주기적 동기화·OS 알림은 보장하지 않습니다. 최초 실행, 기기별 토큰 설정 및 인터넷 연결이 필요합니다. GitHub 장애·계정 제한·향후 무료 정책 변경의 영향은 받습니다.

## 앱 업데이트

0.1.9부터 앱 실행·화면 복귀·네트워크 복구 때 새 버전을 확인하며, 사용 중에도 5분 간격으로 확인합니다. 새 정적 파일을 모두 내려받아 검증한 뒤 입력·드래그·편집창·저장이 끝난 시점에 자동으로 재시작합니다. 실패한 다운로드나 오래된 배포 정보는 실행 중인 버전을 바꾸지 않습니다. HTML은 콘텐츠 필터의 마크업 삽입을 허용하되 버전이 맞는 진입점을 확인하고, 나머지 자산은 SHA-256을 검사합니다. 기기의 일정과 암호화된 연결 정보는 삭제하지 않습니다.

자동 재시작 때 활성 로그인은 최대 60초 동안 워커 메모리의 일회성 전달로 유지합니다. 평문 토큰을 브라우저 저장소나 서버에 추가로 저장하지 않습니다. 브라우저가 워커를 종료하면 기존 잠금 비밀번호로 다시 해제할 수 있습니다. 자동 업데이트와 오프라인 캐시에는 서비스워커가 필요하며, 서비스워커를 차단한 브라우저에서는 온라인 실행만 가능합니다.

이미 열린 0.1.8 이하 화면에는 업데이트 감시기가 없으므로 이번 최초 전환은 다음 앱 열기나 일반 새로고침 때 적용됩니다. 강력 새로고침이나 브라우저 데이터 삭제는 필요하지 않습니다. 0.1.9 이후에는 열린 앱에서도 위 규칙에 따라 자동 적용합니다.

## 개발 및 배포

Node.js가 있으면 `npm run dev`로 `http://127.0.0.1:4173`에서 확인합니다. 빌드 의존성은 없습니다. `npm test`로 병합·데이터 검증 테스트를, `npm run check:public`으로 공개 파일 검사를 실행합니다.

원본 엔진 업데이트는 `node scripts/import-engine.cjs <plugin-directory> <lucide-package-directory>`로 수행합니다. 이 스크립트는 엔진·CSS·폰트·아이콘만 복사하고 런타임 데이터는 복사하지 않습니다. Obsidian의 외부 파일 병합 지점은 웹 저장소의 확정된 결과를 그대로 읽도록 치환합니다. 기간일정 높이 연결, 첨부 UI 제외, 웹 프로젝트 연결 모듈은 `scripts/browser-engine-patches.cjs`의 검증된 웹 전용 패치로 재적용합니다. 엔진 코드가 바뀌어 치환 지점이 달라지면 중단하고 검토해야 합니다. 원본 Obsidian 플러그인 파일은 변경하지 않습니다.

GitHub Pages는 공개 코드 저장소의 `main` 브랜치 `/docs`에서 배포합니다. 앱 수정 시 `package.json` 버전, `index.html`의 부트스트랩 버전, 부트스트랩·워커의 기본 버전을 함께 올리고 `npm run release`로 정적 자산 명세를 생성합니다. `npm test`가 버전 불일치와 갱신하지 않은 자산 해시를 거절합니다. 실행 중인 워커는 자기 버전의 캐시만 읽습니다. 일정 저장소는 Pages를 활성화하거나 앱 코드 저장소에 합치지 않습니다. 배포 전 `node scripts/check-public.cjs <private-calendar-data.json>`으로 실제 일정 문구·구독 주소와 공개 파일의 혼입도 검사할 수 있습니다. 해당 데이터는 읽기만 하며 출력하지 않습니다.

현재 개인 배포 주소: [Sien Calendar 열기](https://wndks10151015-png.github.io/sien-calendar-web/). 공개 방문자는 일정을 볼 수 없고, 본인의 비공개 저장소 연결을 마쳐야 원격 일정을 불러옵니다.

## 확인한 범위

초기 검수: 병합/스키마 단위 검사 12개, Chromium의 5개 뷰·저장/재로드·390px 레이아웃 검사 15개, 모의 GitHub API를 사용한 2기기 충돌·오프라인·토큰 검사 13개, ICS·브라우저 뒤로가기·정적 앱 캐시 검사 6개를 수행했습니다. 로컬 오프라인 검사는 시스템 네트워크 필터의 서비스워커 삽입을 배제하고 원본 서비스워커를 공급한 격리 검사입니다.

원본 문서의 읽기 전용 5개 뷰 렌더링과 레코드 해시 보존 검사 9개, 실제 HTTPS 배포의 익명 접근·정적 캐시·비공개 데이터 404 검사 10개도 통과했습니다. 실제 배포 캐시에서는 서비스워커를 치환하지 않았습니다. 모의 동기화 테스트와 실제 토큰을 이용한 기기 연결은 구분합니다.

실제 비공개 저장소를 연결한 PC·Android 폰·태블릿에서는 검사용 일정의 생성·각 기기에서 수정·삭제 전달과 암호화 저장 후 재실행을 확인했습니다. Android 입력 자동화는 별도 DOM 확인을 병행했으며, 모든 키보드·뒤로가기 조합을 전수 검증했다는 의미는 아닙니다.

0.1.4에서는 터치 포인터를 가진 큰 화면의 모바일 오분류를 수정했습니다. 이 오분류와 모바일 달력 배율이 결합하면 본문이 뷰포트보다 커져 하단바가 사라지고 스크롤이 멈췄습니다. 웹에서는 Obsidian 전용 86px 하단 여백을 사용하지 않습니다. 날짜 드래그 중 네이티브 문자 선택을 막고, 주를 넘는 같은 기간일정은 연결된 레인 전체에서 높이를 공유합니다. 변하지 않은 레인은 기존 높이 캐시를 재사용합니다.

모바일은 카드를 한 번 탭해 가장자리 연결점을 표시하고, 한 번 더 탭하면 상세 편집창을 엽니다. 연결 조작은 드래그로 처리하며, 두 번째 손가락이 들어오면 연결을 취소하고 카메라 확대·축소로 전환합니다. 새 선을 빈 공간에 놓으면 일정 추가 메뉴가 나타나고 바깥 탭·뒤로가기로 닫힙니다. 선택한 가장자리는 대상 일정의 `sienProjectConnectionSides`에 프로젝트·원본 저장 식별자별로 저장합니다. 기존 연결은 기본 오른쪽→왼쪽으로 유지하며, 일정의 주소·메모·제목·삭제 이력은 바꾸지 않습니다. 연결 저장 시 기존 순환·중복·동시 편집 방어와 변경 이력도 유지합니다.
